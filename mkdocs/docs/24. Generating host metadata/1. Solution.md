# Solution

## Setup

Set up the default server:

```terraform
resource "hcloud_server" "g01" {
  name        = module.server.serverName_g01
  image       = module.server.serverImage
  server_type = module.server.serverType
  location    = module.server.serverLocation

  firewall_ids = [hcloud_firewall.SSH.id]
  ssh_keys = [for key in hcloud_ssh_key.sshKeys : key.id]

}
```

There is no need for SSH configuration via _cloud-init_, since the main focus of this exercise is creating metadata, not
a production ready server.

## Module Creation

Create a directory `Modules/HostMetaData` to serve as a reusable module.
Add a `provides.tf` file that contains the required providers, as was done in the prior exercises:

```terraform
terraform {
  required_providers {
    hcloud = {
      source = "hetznercloud/hcloud"
    }
    local = {
      source = "hashicorp/local"
    }
  }
  required_version = ">= 1.5"
}
```

## Templates

Then create a `templates` directory inside that Module, and place a JSON template into it that will later be filled with
the desired metadata.
Interpolate variables the server name, IPv4 and IPv6 addresses, and the server location:

```json
{
  "name": "${name}",
  "network": {
    "ipv4": "${ip4}",
    "ipv6": "${ip6}"
  },
  "location": "${location}"
}
```

## Variables

Since the metadata has to come from a server we create inside the parent module, we need a way to pass the information
to the submodule.
Declare a variable for the server id to be able to access it inside the `HostMetaData` module:

```terraform
variable "server" {
  description = "Server id"
  type        = string
}
```

## main.tf

Define a `data` block to accept an `hcloud_server` from parent module and make its information accessible:

```terraform
data "hcloud_server" "server" {
  id = var.server
}
```

To learn more, visit:

- [HashiCorp - Data](https://developer.hashicorp.com/terraform/language/block/data)

Additionally, implement the local file generation logic via `local_file` as was done in prior exercises:

```terraform
resource "local_file" "hostdata" {
  content = templatefile("${path.module}/templates/hostdata.json", {
    name     = data.hcloud_server.server.name
    ip4      = data.hcloud_server.server.ipv4_address
    ip6      = data.hcloud_server.server.ipv6_address
    location = data.hcloud_server.server.location
  })
  filename        = "gen/${data.hcloud_server.server.name}_metadata.json"
  file_permission = "0644"
  depends_on = [data.hcloud_server.server]
}
```

`${path.module}` allows you to use the module context of the terraform file it is in.
This allows referencing the templates directory inside `Modules/HostMetaData` to pass the previously generated template
to the `templatefile` function.

On the contrary, when declaring the output location, use a relative path without `${path.module}`. This will use the
context of the calling module, meaning the generated file will end up in that module's `gen` directory.

To learn more, visit:

- [HashiCorp - path.module](https://developer.hashicorp.com/terraform/language/expressions/references#path-module)

## Module Import

All that is left to do is importing the module and passing the parameters:

```terraform
module "metaData" {
  source       = "../Modules/HostMetaData"
  server       = hcloud_server.g01.id
  hcloud_token = var.hcloud_token
  depends_on = [hcloud_server.g01]
}
```
