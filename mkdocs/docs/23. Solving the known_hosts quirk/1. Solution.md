# Solution

## Generating a key-pair for the server

Fingerprinting detection can trip if a server has the same IP address as an already known instance.
This happens because a newly created key-pair is now associated with an IP address for a known host with an originally
different SSH key.
A known key-pair should be placed on the server to remedy this problem.

To create a key-pair for the server, a `tls_private_key` resource needs to be created:

```terraform
resource "tls_private_key" "host" { algorithm = "ED25519" }
```

To learn more, visit:

- [Terraform Registry - tls_private_key](https://registry.terraform.io/providers/hashicorp/tls/latest/docs/resources/private_key)

## User data

To be able to pass `user_data` to the server, a local file needs to be created.
Use the `templatefile` function to that end.
It can accept values dynamically, therefore it can supply the server with the previously created SSH key-pair.
Use it to configure the SSH rules as well.

To configure the _cloud-init_ configuration, a template file is needed.
Use `templates/userData.yaml`. It contains the `update` and `upgrade` directives for the system's packages already
covered in previous exercises.

Additionally, it configures the SSH daemon to disallow password and root login, which has already been covered as well.
One change to make is introducing a template string for the user to dynamically configure the username of the admin
account:

```yaml
write_files:
  - path: /etc/ssh/sshd_config.d/99Local.conf
    content: |
      PermitRootLogin no
      PasswordAuthentication no
      AllowUsers ${devopsUsername}
```

The template string can be used to define the `users` directive as well.
Authorized SSH keys can be passed into the configuration with interpolation dynamically as well.
The `ssh_authorized_keys` placeholder should be replaced with a map of string, which should contain the desired SSH keys
as values.
These values can be accessed via the `values` function:

```yaml
${yamlencode({
  users = [
  {
    name                = devopsUsername
    groups              = [ "users", "admin" ]
    sudo                = "ALL=(ALL) NOPASSWD:ALL"
    shell               = "/bin/bash"
    ssh_authorized_keys = values(ssh_authorized_keys)
  }
]
```

Now the SSH keys for the server can be defined and encoded via `yamlencode` as well.
Add a placeholder for both public (`host_ed25519_public`) and private (`host_ed25519_private`) keys:

```yaml
  ssh_keys = {
  ed25519_private = host_ed25519_private
  ed25519_public  = host_ed25519_public
  }
```

The resource should provide values for all placeholders so they can be interpolated correctly when generating the
output.
Place the output in a generated file directory (e.g. `gen`) via the `filename` key.
Pass the content through the `templatefile` function, and provide the variable values which should be interpolated.
Use the generated `tls_private_key` for `host_ed25519_public` and `host_ed25519_private`.
Pass the desired loginUserName (e.g. the default user `devops` from the `config.tf.template` file), and the desired SSH
public keys which should be authorized to log in as that user.

```terraform
resource "local_file" "user_data" {
  filename = "${path.module}/gen/user_data.yaml"
  content = templatefile("${path.module}/templates/userData.yaml", {
    host_ed25519_private = tls_private_key.host.private_key_openssh
    host_ed25519_public  = tls_private_key.host.public_key_openssh
    devopsUsername       = module.config.loginUserName
    ssh_authorized_keys  = module.config.authorizedKeys
  })
  depends_on = [tls_private_key.host]
}
```

## Server creation

Add the following line to the server resource you have been using in the previous exercises to pass the previously
created _cloud-init_ configuration:

```terraform
user_data = local_file.user_data.content
```

It should look like the following snippet:

```terraform
resource "hcloud_server" "g01" {
  name        = module.server.serverName_g01
  image       = module.server.serverImage
  server_type = module.server.serverType
  location    = module.server.serverLocation

  ssh_keys     = [for key in hcloud_ssh_key.sshKeys : key.id]
  firewall_ids = [module.firewall.firewallID]
  user_data    = local_file.user_data.content

  depends_on = [local_file.user_data]
}

```

## Known Hosts

To be able to pass the generated key-pair as a known host for the IP the server was just created with, a _known_hosts_
file has to be created.
Combine the server's `ipv4_address` with the `tls_private_key` to form the contents of the file.
Place the generated file in your `gen` directory and set the appropriate permissions.

```terraform
resource "local_file" "known_hosts" {
  content = join(" ",
    [hcloud_server.g01.ipv4_address, tls_private_key.host.public_key_openssh]
  )
  filename        = "${path.module}/gen/known_hosts"
  file_permission = "644"
  depends_on = [hcloud_server.g01]
}
```

## SSH wrappers

The wrapper scripts can now be created to facilitate easier interfacing with the server via SSH.

### SSH wrapper

Use the template `templates/ssh.sh` as a base for the generated wrapper.
It calls `scp` with the generated _known_hosts_ file, preventing the detection of changed SSH keys without having to
alter the system's base _known_hosts_ file.

```bash
#!/bin/bash
ssh -i "${pk}" -o "UserKnownHostsFile=\"${genDir}/known_hosts\"" devops@${ip} "$@"
```

Interpolate the variables via the `templatefile` function.<br>
Pass the server's IP address via the `ip` variable.<br>
Pass the path to your private key file via the `pk` variable.<br>
Pass the absolute path of your `gen` directory via the `genDir` variable.

Save the generated script to your `bin` directory (or any other directory set in `$PATH`) to be able to execute it from
any arbitrary working directory.
You may set the `bin` directory via the `bin` output directive in `Modules/Conf/config.tf.template`.
Set the file permissions accordingly via `file_permission`:

```terraform
resource "local_file" "ssh_script" {
  content = templatefile("${path.module}/templates/ssh.sh", {
    ip     = hcloud_server.g01.ipv4_address
    pk     = module.config.pk
    genDir = "${abspath(path.module)}/gen"
  })
  filename        = "${module.config.bin}/ssh${hcloud_server.g01.name}"
  file_permission = "755"
  depends_on = [local_file.known_hosts]
}
```

The script can now be called via the concatenated strings `ssh` ad the server name.

### SCP wrapper

The script takes two parameters, which are the positional parameters taken by `scp`.
It checks for their existence via `$# -lt 2` to ensure the command is being invoked correctly, but it doesn't check if
the parameter contents are valid.
The script the calls `scp` with the generated _known_hosts_ file, to the same end as the `ssh` wrapper does.

```bash
#!/usr/bin/env bash
if [ $# -lt 2 ]; then
   echo "usage: .../bin/scp ... devops@${ip} ..."
else
   scp -i "${pk}" -o "UserKnownHostsFile=\"${genDir}/known_hosts\"" "$@"
fi
```

SCP wrapper generation works in the exact same manner as it did for the SSH wrapper:

```terraform
resource "local_file" "scp_script" {
  content = templatefile("${path.module}/templates/scp.sh", {
    ip     = hcloud_server.g01.ipv4_address
    pk     = module.config.pk
    genDir = "${abspath(path.module)}/gen"
  })
  filename        = "${module.config.bin}/scp${hcloud_server.g01.name}"
  file_permission = "755"
  depends_on = [local_file.known_hosts]
}
```

The script can be called via the concatenated strings `scp` ad the server name.
