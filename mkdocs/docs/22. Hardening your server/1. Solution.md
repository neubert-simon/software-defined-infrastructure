# Solution

## Firewall

Supplying a firewall that only allows SSH traffic can be achieved by supplying only the rule name `ssh` to the
`Firewall` module:

```terraform
module "firewall" {
  source = "../Modules/Firewall"
  rules = ["ssh"]
}

```

To allow web traffic, add `"http"` to the list of rule names:
```rules = ["ssh", "http"]```

## Upgrading the server automatically

To upgrade the distribution at server creation time, the following directives can be added to the _cloud-init_
configuration:

```yaml
package_reboot_if_required: true
package_update: true
package_upgrade: true
```

The `package_reboot_if_required` directive ensures that the system reboots if necessary to complete the operation.

## Installing and running services

The exercise calls for three services, _nginx_, _fail2ban_, and _plocate_.
To install them, add their respective name to the `packages` directive, and enable it with `systemctl` under the
`run-cmd` directive:

```yaml
packages:
  - nginx
  - fail2ban
  - plocate

runcmd:
  - systemctl enable fail2ban
  - systemctl enable nginx
  - systemctl enable plocate
  - sudo updatedb
```

### Plocate

_plocate_ additionally requires `sudo updatedb` to initialize the index-based `locate` command.
To learn more, visit:

- [plocate](https://plocate.sesse.net)

## Devops user

To set up the user `devops`, _cloud-init_ was employed.
Add the following line to assign `sudo` rights to the user `devops`:

```bash
sudo: ALL=(ALL) NOPASSWD:ALL
```

The complete user configuration should look like this:

```yaml
users:
  - name: devops
    groups: users, admin
    sudo: ALL=(ALL) NOPASSWD:ALL
    shell: /bin/bash
    ssh_authorized_keys:
      - YOUR PUBLIC KEYS HERE
```

Dynamic user creation will be done in the next exercise,
see [Ex. 23 - Solving the known_hosts quirk](../23.%20Solving%20the%20known_hosts%20quirk/1.%20Solution.md)

## SSH

### SSHD Configuration

To alter the default ssh daemon configuration, _cloud-init_ was employed to write a configuration file to
`/etc/ssh/sshd_config.d/`.
Both root login and authentication via password were disabled via `PermitRootLogin no` and `PasswordAuthentication no`
respectively.

```yaml
write_files:
  - path: /etc/ssh/sshd_config.d/99Local.conf
    content: |
      PermitRootLogin no
      PasswordAuthentication no
      AllowUsers devops
```

To learn more, visit:

- [sshd_config(5) - Linux man page](https://linux.die.net/man/5/sshd_config)
