# Solution

## Server creation with Terraform

To avoid having to create the server manually, server creation via Terraform was set up.

Run the following command in the directory `20. Cloud-init by Terraform` or execute the _apply.sh_ script with the command line argument `20` to create the server via Terraform.

``` bash
terraform init && terraform apply
```

The results were the exact same as described in [Exercise 19. Results](../19.%20Cloud-init%20for%20starters/2.%20Result%20Verification.md).

## Creating the Terraform configuration

### Cloud provider

To be able to access the Hetzner API, the `hcloud` cloud provider needs to be initialized:

```terraform
terraform {
  required_providers {
    hcloud = {
      source = "hetznercloud/hcloud"
    }
  }
  required_version = ">= 0.13"
}
```

#### Hetzner Cloud API token

To be able to purchase a server instance, the generated API token (as per [Prerequisites](../index.md#prerequisites)) has to be read from the shell environment:
```terraform
provider "hcloud" {
token = var.hcloud_token
}
```

To be able to source the token from a confidential `.env` file, follow the instructions in the [Templates](../0.%20Preliminaries/Templates.md) preliminary.
Alternatively, you can export the secret directly to be stored as an environment variable in your current shell session:
```bash
export TF_VAR_hcloud_token=YOUR_TOKEN_HERE
```

To learn more, visit:<br>
[The Linux Documentation Project - Bash Variables](https://tldp.org/LDP/Bash-Beginners-Guide/html/sect_03_02.html)

### Server creation

```terraform
# Create the server
resource "hcloud_server" "g01" {
  name         = "g01"
  image        = var.serverImage
  server_type  = var.serverType
  location     = "nbg1"

  # Post server creation init script
  user_data    = file("cloud-init.yaml")
}
```

To read more about server resource creation, visit:
- [Terraform - Resources](https://developer.hashicorp.com/terraform/plugin/framework/resources)
- [Terraform Registry - hcloud_server](https://registry.terraform.io/providers/hetznercloud/hcloud/latest/docs/resources/server)


### Variables

Commonly used values have been stored in variables for ease of access:
```terraform
variable "hcloud_token" {
  description = "Hetzner API token"
  type = string
  nullable = false
  sensitive = true
}

variable "serverImage" {
  description = "Server image"
  type = string
  nullable = true
  default = "debian-13"
}

variable "serverType" {
  description = "Server type"
  type = string
  nullable = true
  default = "cx23"
}
```

To learn more about Terraform variables, visit:<br>
[Terraform - Variables](https://developer.hashicorp.com/terraform/enterprise/variables)

### Output

To be able to connect to the server immediately after the init-script has finished, an output directive was added in the file `output.tf`.
It outputs the IPv4 address the server was assigned:

```terraform
output "ip" {
  value = hcloud_server.g01.ipv4_address
}
```

To learn more about Terraform output, visit:<br>
[Terraform - Output](https://developer.hashicorp.com/terraform/tutorials/configuration-language/outputs)
